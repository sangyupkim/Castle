# 듀얼 프론티어 — 아트 에셋 목록 v1.0

> 작성: 2026-08-28 · 대상 빌드: v0.6.0
> 지금 게임에 들어 있는 이미지는 **딱 3장**입니다 — 타이틀 배경(`mainpage.png`)과 PWA 아이콘 2종.
> 화면에 보이는 나머지 전부가 이모지 글자와 `fillRect` / `arc` 도형입니다.
> 이 문서는 "무엇을 그림으로 바꿔야 진짜 게임처럼 보이는가"를 우선순위대로 정리한 것입니다.

## 0. 먼저 알아야 할 기술 제약

| 항목 | 값 | 에셋에 주는 영향 |
|---|---|---|
| 캔버스 | 480 × 800 (논리 픽셀) | 모든 크기는 이 좌표계 기준 |
| DPR | **최소 2배 강제** (`resize()`) | **모든 에셋은 @2x로 제작**. @3x는 선택 |
| 상단 격자 | 9 × 7칸, 한 칸 **53 × 50** | 타워·바닥 타일의 기준 박스 |
| 하단 아레나 | 480 × 330 | 개체가 최대 28마리 동시에 존재 |
| 아레나 개체 반지름 | 6 ~ 11px (보스 20) | **지름 12~22px** — 지금 크기로는 그림이 안 읽힌다 |
| 렌더 | Canvas 2D `drawImage` | PNG(스프라이트 아틀라스)가 SVG보다 유리 |

> ⚠️ **가장 중요한 결정 하나** — 아레나 유닛의 표시 반지름이 7.5px입니다.
> 여기에 캐릭터 그림을 넣으면 15px짜리 점이 됩니다. 그림으로 갈 거라면
> **아레나 개체를 지름 26~32px로 키우고 동시 생존 상한(28)을 16~20으로 낮추는**
> 리밸런싱이 아트보다 먼저입니다. 안 그러면 예쁜 그림이 서로 겹쳐서 안 보입니다.

## 6. 코드 쪽에서 먼저 해야 할 일

에셋을 받기 전에 준비해둘 것들입니다. 이거 없이 그림만 오면 붙일 데가 없습니다.

1. **에셋 로더** — 지금은 `_titleImg` 하나를 `new Image()`로 즉시 로드합니다.
   `Promise.all` 기반 프리로더 + 로딩 화면이 필요합니다.
2. **아틀라스 + 좌표 JSON** — 400장을 개별 요청하면 모바일에서 느립니다.
   2048×2048 아틀라스 2~3장으로 묶고 `{name: {x,y,w,h}}` JSON을 씁니다.
3. **폴백 유지** — `drawSprite(name, x, y)`가 이미지가 없으면 **지금의 이모지 렌더로 떨어지게** 만들면,
   에셋을 한 장씩 받아 붙이면서도 게임은 계속 돌아갑니다. 이게 제일 중요합니다.
4. **아레나 개체 크기 재조정** — 위에서 말한 반지름 7.5 → 13~16 문제.
   동시 생존 상한도 28 → 16~20으로 함께 조정해야 합니다.
5. **애니메이션 상태 기계** — `idle / move / attack / die` 4상태와 프레임 타이머.
   지금 개체에는 `flashTimer` 정도밖에 없습니다.
6. **레이어 정렬** — 아레나에서 y좌표 순으로 그려야 앞뒤가 맞습니다 (지금은 배열 순서).
